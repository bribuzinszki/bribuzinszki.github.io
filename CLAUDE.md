# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal design portfolio (Learning Experience Design / AI literacy) served by GitHub Pages at https://bribuzinszki.github.io/. It is a plain static site built on the **Phantom** template by HTML5 UP (CCA 3.0, attribution comment kept at the top of every page). There is no package.json, no build pipeline, no tests and no linter; pushing to `main` deploys.

Local preview: `python3 -m http.server` from the repo root, then open http://localhost:8000/.

## Page structure

Every page is a standalone HTML file at the repo root that repeats the same shell: `<head>` meta/OG tags (with absolute `https://bribuzinszki.github.io/...` URLs), `#header` with logo and contact icons, the `#menu` nav, `#main`, `#footer`, then the template scripts (`jquery.min.js`, `browser.min.js`, `breakpoints.min.js`, `util.js`, `main.js`). There are no includes or templates, so **changes to the header, menu, footer or contact links must be made in every HTML file.**

Page types:
- `index.html`: landing page with three `.tiles` sections (`#try-it`, `#case-studies`, `#frameworks`). Each tile is an `<article class="styleN">` with an image and a link; tiles pointing at `generic.html` are placeholders. A commented-out block holds tiles that are hidden for now.
- `case-*.html`: case studies using the `cs-*` classes (`.cs-lead`, `.cs-overview`, `.cs-shot`/`.cs-shot-bar` browser-frame screenshot, `.cs-facts`, `.cs-pager` back/next links). The pager links form a chain between case studies, so adding or reordering one means updating its neighbours.
- `framework-*.html`: framework write-ups.
- `*-exercise.html` and `eu-ai-act-high-risk.html`: self-contained interactive modules. Each has its own scoped `<style>` block and inline `<script>` inside `#main`; their CSS is namespaced under a module id (e.g. `#aia-module` with `--aia-*` custom properties) so it doesn't leak into the template styles.
- `agents-course.html` + `agents-module-*.html`: the story-based course "Working with AI Agents" (fictional product Taskzilla, company BestSolutions). The landing tile and menu point to the course page, which links to each module. Unlike the other interactive pages, these share one stylesheet, `assets/css/agents-course.css` (everything scoped under `#tz`); each page keeps its own inline script. Modules are single scrolling pages (no click-to-reveal), with a sticky contents list and independent activities. Progress is saved in `localStorage` under `tz-agents-course` (try/catch) and read by the course page. Modules 1 to 3 exist so far; the course script lives in a separate review doc, not in this repo.
- `ai-recruiting-scenario.html`: "Same Tool, Two Countries", an English-only branching scenario on AI in recruiting. A Brazilian company takes its fictional AI recruiting tool (ZapTalento) from São Paulo to Stuttgart, and every feature has to clear two levels: "Does it make sense?" (ROI, with the meters days to offer / days to a good hire) and "Is it legal?" (EU AI Act, GDPR, BetrVG, AGG vs. LGPD, Lei 9.029, PL 2338). It follows the interactive-module pattern: CSS scoped under `#stc-module`, all text in the JSON block `id="stc-content"`, progress in `localStorage` under `stc-module-v1`. The engine reads option effects (meter deltas, flags, go-live weeks) from the JSON; the ending rules are in `endingId()`. The legal content carries a status date (16 November 2026) in the JSON and on the page: update both when the law changes. The script, legal review notes and branch walk live in a Claude Doc, not in this repo; a book quote for Level 1 is a placeholder (`scenes.l1intro.bookBeat`, empty until confirmed).
- `sell-this-banana.html`: "Sell this Banana", a pixel-art sales game for junior salespeople. Silly banana scenes, real sales skills; after each level a short "Back at the office" step applies the skill to a fictional product, Karl-Klein 2.0 (a small German language model sold on sovereignty). Prototype with Levels 1 (beach kiosk) and 2 (gym in Stuttgart) of 6. It's in the menu and has a tile on `index.html`, both placed before "Working with AI Agents". Like the agents course it uses shared files instead of inline code: `assets/css/sell-this-banana.css` (scoped under `#stb`), `assets/js/sell-this-banana-art.js` (all pixel art and the pixel font drawn in code, no image or font files; exposes `window.STBArt`) `assets/js/sell-this-banana-sound.js` (original music and effects synthesized with Web Audio, off until the player turns it on) and `assets/js/sell-this-banana.js` (engine). All text lives in the JSON block `id="stb-content"` as a `levels` list; each level has a `type` with its own runner in the engine: `kiosk` (Level 1: customers as trees of nodes, each choice with ripeness cost, trust change, sale steps, flag and outcome) and `discovery` (Level 2: questions that reveal need cards and unlock follow-ups, then a pitch built from need, feature and line). Every level shares the fail card, win card, office steps (`single` or `multi`), fact card and end screen; the title screen is a level select. The game stores nothing in the browser yet; when saved progress comes, its key goes into `privacy.html` as below.
- `maliciousagents.html`: "ARTEX: When Security Agents Change Sides", an interactive info page (English, with a German version, see below) explaining the agentic penetration-testing framework ARTEX (open-source, built for authorised testing, then widely misused in 2026) for a non-technical to semi-technical audience: what it is and how it's built, its dual-use slide into real attacks, why the trend is growing, and the defences that matter. The file name is deliberately generic, not `artex.html`, so nobody mistakes the repo for one that holds a copy of the tool; keep it that way. It's in the menu (last under Try It Yourself, after "Working with AI Agents") and has the last tile in `#try-it` on `index.html` (`style6`, `images/tile-malicious-agents.jpg`: the title robot on a teal/pink split background, rendered from the same pixel grid). There is a German version, `maliciousagents-de.html` ("ARTEX: Wenn KI-Agenten die Seiten wechseln", du, gender-neutral forms such as Angreifende/Betreibende), reached only through the EN | DE switch under the title (`.ma-lang`, plus `hreflang` alternates in both heads); it has no menu entry and no tile. The two pages share code like the agents course: styles in `assets/css/maliciousagents.css`, logic in `assets/js/maliciousagents.js`, and every text the widgets show lives in each page's JSON block `<script type="application/json" id="ma-strings">` (same shape in both; templates use `{placeholders}`, `_one`/`_other` plurals; the engine buttons use `data-m="A|B|C"` with display names from the JSON; the German opening names carry their articles because the templates use them in the accusative). **Any content change must be made on both pages, in the prose and in the JSON.** On the German page the header, menu and footer, the source list and the designer's notes stay English and are marked `lang="en"`; the German danger illustrations have wider badges and sign and 9px bar labels so the longer words fit. Everything is scoped under `#ma-module` with `--ma-*` custom properties, and the surrounding prose keeps the template styles (tokens only on `#ma-module`, typography only on `.ma-widget`). The in-widget resets (now in the shared CSS file) are deliberately low-specificity (`#ma-module button { all: unset }` and `#ma-module :where(.ma-widget) :where(p, h3, ul, li, label)`) so every `#ma-module .ma-x` component rule beats them; adding a class to either reset silently wipes component styles (this already caused unreadable log text and unstyled buttons once). Component class names must also be unique across the page's widgets: the diagram's model box was once named `.ma-model`, the same class as the loop widget's engine buttons, and its styles squashed those buttons (the box is now `.ma-llm`). Next to the title sits `.ma-hero-art`, a pixel-art robot agent in a split white-hat / black-hat fedora with a shield and a key: inline SVG paths drawn from a 32×32 grid (no image file, `shape-rendering="crispEdges"`, shown at whole multiples, 160px and 96px on phones), with an eye blink that stops under reduced motion. Interactive widgets and visuals, each tied to one learning outcome (see the designer's notes on the page): `#ma-layers` (an HTML/CSS diagram in "So what is ARTEX?": the framework box holds three agent chips plus notebook, tools and dashboard, while the model sits outside it and the agents "plug into" it, with three colour-keyed definitions below; model = blue, agent = teal, framework = dark), `#ma-loop` (chatbot vs. agents on the same harmless goal; it opens in Chatbot mode, where the reader does the legwork by tapping the Act/Check/Note step chips and pressing Report back, and at the end presses Write report because the chatbot hands the write-up back (the agents' lead hands over a finished report), while in Agent team mode the agents run the loop with each log line tagged by role and the chips only explain who does what; four counters contrast steps done without you, steps you did, pauses waiting for you and times a model refused. The engine picker does real work: Model A is strict, B in between, C never refuses (thresholds in `MODELS`), and a model refuses when the "break-in signal" it can see reaches its threshold. Refusals sit at fixed points, not random: in Chatbot mode every message carries the whole chat, so each reported "it opens" raises the signal (A refuses after the cellar window, B after the garage), and a swap means a new chat the reader has to fill in with "Explain again"; in Agent team mode the model only sees one small step labelled as an authorised test, so only the garage push (`sig: 1` in `LINES`) trips Model A, the run pauses until the reader, as operator, swaps the engine, and the agents pick up where they stopped because the progress lives in the notebook. A "What the model sees" strip under the engine pill (`#ma-loop-sees`) shows the whole chat vs. one labelled step. Reset and switching mode put the engine back on Model A), `#ma-dangers` (three static illustrated cards with inline SVG for the three dangers: same tool in two hands, a polite guardrail a copy deletes, a lowered bar; replaced an earlier timeline widget that didn't land), `#ma-graces` in the "Before you unplug the router" section (`#limits`: four sourced limits that balance the page: loud, deterred by protection, needs an open door, slowed by model guardrails; deliberately no "it's expensive" point, because Check Point estimated whole campaigns at roughly $150–1,500 in AI fees), `#ma-drive` (a "who's driving?" autonomy slider), `#ma-sort` ("worth it or security theatre?": 10 cards built on CERT-EU's ARTEX advice, five CERT-EU actions in plain words and five near-misses whose feedback names CERT-EU's fix, each with a right away / soon / ongoing label from CERT-EU's time frames; order mixed, pairs never shown together) and the `#ma-quiz` quick check (built on the `inference-exercise.html` quiz pattern, renamed `ma-`; under its own h2 `#check`, placed last, right after the "Four things to remember" list `#remember` (German "Halten wir also fest:"), which follows the sorting exercise: one question per takeaway, and a wrong answer links back to its section). Terminology rule: ARTEX is a *framework* (Google: "autonomous, multi-agent … pentesting and offensive command-and-control platform"); the *agents* are the lead, planners and workers inside it; the *model* is the external LLM they run on. Never call ARTEX "an agent"; say "frameworks like ARTEX" when you mean the tool. Content rule: conceptual and defensive only — no attack steps, commands, tool settings or links to copies of the tool; the one hands-on widget uses a locksmith-checking-a-house metaphor, never a real technique. Nothing is stored in the browser and nothing loads from other servers, so `privacy.html` is unchanged. Both pages carry a status date (17 November 2026, "Stand: 17. November 2026") and a sourced, hedged account because the public reporting was still shifting and disagrees on details; update the status date and facts when the story moves.
- `privacy.html`: privacy notice in English and Brazilian Portuguese (LGPD), linked from the footer `.copyright` list on every page, not from the menu. It has a "Delete my saved progress" button that clears every `localStorage` key the site uses.
- `elements.html` / `generic.html`: original template reference pages.

When adding a page, also add it to the `#menu` list in every file and, if relevant, a tile on `index.html` (tile images live in `images/tile-*.jpg`, heroes in `images/hero-*.jpg`).

## Privacy

The site sets no cookies, runs no analytics and loads nothing from other servers; the font (Source Sans Pro) is self-hosted in `assets/webfonts/` with `@font-face` rules at the top of `main.css` / `main.scss`. Keep it that way, or update `privacy.html` in the same change:
- a new `localStorage` key goes into both tables on `privacy.html` (EN and PT) and into its `KEYS` list;
- any third-party request (fonts, scripts, embeds, analytics, iframes) needs a section in both languages, and cookies or analytics would need consent under the LGPD.

## EU AI Act module

`eu-ai-act-high-risk.html` is bilingual. All text lives in two JSON blocks with identical structure: `<script type="application/json" id="aia-content">` (German original) and `id="aia-content-en"` (English translation). Any content change must be made in both. Language is chosen by the DE | EN switch, `?lang=de` / `?lang=en`, or the choice remembered in `localStorage` (default English). `?review` highlights corrected and new texts. Progress is stored in `localStorage` with try/catch fallbacks to memory.

## Styles

Source Sass lives in `assets/sass/` (`main.scss` imports `libs/`, `base/`, `components/`, `layout/`); custom additions include `components/_case-study.scss`. The browser loads only the compiled `assets/css/main.css`, which is committed. No Sass build is configured in the repo, so when changing a partial, apply the same change to `assets/css/main.css` (or recompile with the `sass` CLI) and keep the two in sync. Page-specific styling for interactive modules goes in that page's inline `<style>` instead.
